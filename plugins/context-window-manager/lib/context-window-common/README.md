# context-window-common

Shared library for the context-window family. There is no `/context-window-common` slash command; this directory ships helpers that the two user-facing skills depend on. Bump this skill independently of its consumers; each consumer references the live helper, not a snapshot.

## Modules

- `context_schema.py`: the schema for, and render/parse of, the `### Session Metadata` block that the handoff skill appends to each `CONTEXT-*.md` file. `SessionMetadata` is the dataclass of the 20 recorded values, each defaulting to its "nothing known" case. `render_metadata_block(meta)` produces the block text; `parse_metadata_block(text)` reads it back, returning scalars as `str | None` (`n/a` and missing keys map to None) and the two list keys, `commits` and `adrs`, as `list[str]`. List items render as indented `  - item` lines under their `- key:` header and are collected only while they directly follow it, so a stray bullet in prose cannot be swept in. Every count-valued key (`staged`, `unstaged`, `untracked`, `stash_count`, `remote_ahead`, `remote_behind`) is optional: `n/a` when its probe never ran or failed, a bare integer (including 0) once the probe has actually answered, so a failed probe cannot be mistaken for "checked, found nothing." `context_filename(now=None)` generates the collision-resistant output filename (`CONTEXT-{timestamp}-{6-hex-suffix}.md`) so two parallel sessions handing off within the same second never overwrite each other's file. Also owns the save-path contract: `SAVE_ROOT` (`~/.config/sct/context-window-manager`, overridable via the `CWM_SAVE_ROOT` env var), `repo_slug(cwd)` (git-toplevel basename, else cwd basename), and `save_dir(cwd, create=False)` (`SAVE_ROOT/<repo-slug>`, made on demand with owner-only permissions when `create=True`), plus the shared constants `CONTEXT_GLOB` (`CONTEXT-*.md`) and `META_HEADING` (`### Session Metadata`). When the handoff runs outside a git repo, the helper renders `n/a` values so the block is always well-formed.
- `session_capture.py`: the read-only probes that fill a `SessionMetadata`. `collect_git(cwd)` reads HEAD (full and short), branch, working-tree state with staged / unstaged / untracked counts, stash depth, upstream name with ahead/behind and pushed state, and the commit list as `<shortsha> <subject>`, scoped to what the branch added over its base, capped at 20, and falling back to recent history when HEAD is itself the base. Working-tree and stash counts come back `None` when their git probe itself fails (timeout, broken submodule), never a guessed zero. Commit subjects are attacker-influenceable text, so backticks are stripped from each one before capture: left verbatim, a backtick-wrapped `~/...` path in a subject would be picked up by `verify_refs.extract_refs` when resume scans the rendered block, and probed against the filesystem. `collect_context(meta, ...)` adds the task id (explicit, else parsed from the branch name), the task file path, the PR number and URL, a `tdd_plan_path` recorded only when the task file lacks a populated `## TDD Plan`, and the session's ADRs. The PR lookup takes an injectable `gh_runner` so tests never shell out, and skips `gh` entirely when the repo has no remote. When the default `gh pr view` probe returns no PR (common in worktrees whose local branch name differs from the remote head), a second probe lists every PR state for the recorded remote head and accepts exactly one candidate whose `headRefOid` matches the tracked ref. The vault location is never hardcoded: pass `vault_root` or set `COBTASK_VAULT_ROOT`.
- `git_drift.py`: `compute_drift(stored_sha, stored_branch, cwd)` compares the stored HEAD SHA against the current HEAD and reports ahead/behind counts, whether the stored SHA still resolves, whether the stored branch still exists, and the current branch. `verify_commits(commits, cwd)` splits each `<shortsha> <subject>` entry and probes the sha with `git cat-file -e`, flagging a commit a rebase or force-push dropped; `recompute_remote(cwd)` recomputes ahead/behind against `@{upstream}`, returning None counts with a note when there is no upstream. All three degrade gracefully when `cwd` is not a git repo (returns `is_git` false / a note rather than raising), so the resume skill can still show the rest of its report.
- `verify_refs.py`: `extract_refs(text)` pulls backticked path references out of the handoff prose; `verify_refs(refs, cwd)` stats each one against the working tree and reports whether the path still exists and whether any cited line number is still in range. This is how the resume skill flags stale references before you choose a direction.
- `verify_continuity.py`: `verify_continuity(meta, cwd, gh_runner=None)` is the resume-side verification of the expanded handoff fields, consuming the `parse_metadata_block` dict. It reports cwd match, cobtask/TDD-plan/ADR path existence, the PR's re-queried `current_state` (read-only `gh pr view`, injectable runner so tests never shell out), commit resolvability and working-tree divergence (reusing `git_drift` and `session_capture.collect_git`), and a recomputed remote ahead/behind. Every probe degrades to a structured note rather than raising, so a missing `gh`, an offline network, or a deleted PR/branch/upstream never crashes resume. The resume skill folds this into its single `report.continuity`.

- `retention.py`: once/day archival of stale `CONTEXT-*.md` handoffs. `retention_days(env=None)` resolves the retention window from `SCT_CWM_RETENTION_DAYS` (default 30) and raises `RetentionConfigError` on a non-int or `< 1` value, so a bad config fails loud instead of silently disabling pruning. `parse_context_timestamp(name)` reads the `CONTEXT-<YYYY-MM-DD-HH-MM-SS>` filename as the authoritative age clock; `file_age_days(path, now)` falls back to mtime only when the name is unparseable. `prune(save_root, now, days)` moves `CONTEXT-*.md` files older than `days` into the terminal `zArchives/<slug>/` sibling under `SAVE_ROOT` using `shutil.move` (never a delete, honoring the `rm` ban), relocating a whole per-repo-slug dir only when every handoff under it is stale and merging file-by-file when a prior archive dir already exists; it never scans `zArchives/`, so archived files are never re-processed. `maybe_prune(save_root, today, env=None)` gates the walk to at most once per calendar day via a `.last_prune` marker at the save root, and propagates config errors before touching the filesystem. `zArchives/` is terminal: nothing under it is ever auto-deleted or re-pruned. Consumed by the handoff pre-flight validator.

Each module has a sibling `test_*.py`. The library is imported by the two sibling skills via a `sys.path` insert into this directory, so the consumers always call the live helper rather than a copied snapshot.

## Rules

- Read-only library. Helpers stat and parse; they never mutate files.
- No external dependencies. The metadata block shape is narrow enough that a hand-rolled render and parse pair is faster and safer than dragging in a YAML library.
- Helpers degrade rather than raise on boundary conditions (no git repo, unresolvable SHA, missing path), so the consuming skills can always render a partial report.
