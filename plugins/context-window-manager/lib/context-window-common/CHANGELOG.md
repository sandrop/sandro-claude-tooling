# Changelog

## 0.8.0 - 2026-09-07

- Add `retention.py`: once/day archival of stale `CONTEXT-*.md` handoffs into a terminal `zArchives/` sibling under `SAVE_ROOT`, move-only (never deletes; honors the `rm` ban). `retention_days(env=None)` resolves `SCT_CWM_RETENTION_DAYS` (default 30) and raises `RetentionConfigError` on a non-int or `< 1` value rather than silently disabling pruning. `parse_context_timestamp(name)` reads the `CONTEXT-<YYYY-MM-DD-HH-MM-SS>` filename as the authoritative age clock (optional hex suffix), and `file_age_days(path, now)` falls back to mtime only when the name is unparseable. `prune(save_root, now, days)` moves stale files into `zArchives/<slug>/`, moving a whole per-repo-slug dir only when every `CONTEXT-*.md` under it is stale (merging file-by-file when a prior archive dir already exists), and never scans `zArchives/` (no re-archiving loop). `maybe_prune(save_root, today, env=None)` gates the walk to at most once per calendar day via a `.last_prune` marker at the save root, propagating config errors before any walk. Consumed by the context-window-handoff pre-flight validator.
- Harden `prune` against exposure and concurrency. The `zArchives/` root and each archived slug dir are now created owner-only (`0o700` via `_ensure_private_dir`), matching the live slug dirs, so an archived handoff is never more world-readable than it was live. A file-level archive never overwrites an existing archived file (`_collision_free_dest` writes a distinct `.dupN` name instead), keeping the move-only, never-delete guarantee even after a manual restore reintroduces a same-named handoff. `prune` is now idempotent and safe under a concurrent same-day prune: a source moved by another handoff between selection and move is skipped rather than raising, so a race loses no data and surfaces no spurious error.
- Add a `keep_dir` parameter to `prune` and `maybe_prune` so the caller's active handoff directory is never relocated wholesale. Without it, a repo idle longer than the retention window (its slug dir holds only stale handoffs and has no prior archive) had its whole directory moved into `zArchives/` by the same pre-flight that had already reported that directory as the write target, so the next handoff wrote to a vanished path. With `keep_dir` set to the active save dir, that dir's stale files are still archived file-by-file, but the (now-empty) directory is left in place and writable.
- Stop skipping dot-prefixed slug dirs in `_iter_slug_dirs`. `repo_slug` is `<toplevel-basename>-<hash>`, so a repo whose git toplevel name begins with a dot (e.g. `~/.claude` -> `.claude-<hash>`) has a legitimate dot-prefixed slug that was being excluded from retention forever; its handoffs never got archived. The walk now skips only the reserved `zArchives/` entry (the `.last_prune` marker is a file and is already excluded by the `is_dir()` guard).

## 0.7.2 - 2026-09-05

- Let a latency-sensitive caller bound the `repo_slug` git probe. `repo_slug(cwd, deadline=None)` and `save_dir(cwd, create=False, deadline=None)` accept an optional deadline (any object with an `.expired()` method); when the shared budget is already spent the git `rev-parse --show-toplevel` is skipped and the cwd fallback is used, so a caller that shares one budget across several probes degrades within roughly one `_GIT_TIMEOUT` total instead of adding another. Callers that pass nothing keep the original always-probe behavior. Expose `session_capture.Deadline` as a public alias of the internal `_Deadline` so sibling modules (the PreCompact hook) can construct one shared budget. Consumed by the context-window-manager PreCompact failsafe hook.

## 0.7.1 - 2026-09-01

- Relocate the default `SAVE_ROOT` from `~/.claude/.sct/context-window-manager` to `~/.config/sct/context-window-manager`. The `CWM_SAVE_ROOT` env override still wins, and the per-repo `<repo-slug>` namespacing under the root is unchanged. `save_dir(create=True)` enforces owner-only permissions on the per-repo handoff directory. Handoffs already written under the old root are left in place; there is no migration and no fallback read of the old path. Bumps to 0.7.1 because 0.7.0 already shipped the `worktree_toplevels` helper.

## 0.7.0 - 2026-08-25

- Add `context_schema.worktree_toplevels(cwd)`: absolute, resolved toplevel paths of every git worktree linked to `cwd`'s repo, parsed from `git worktree list --porcelain` (primary first). Degrades to `[]` outside a git repo or when git is unavailable, mirroring `repo_slug`'s degrade-to-local behavior so callers never guard git absence. Consumed by the resume validator's cross-worktree candidate scan.

## 0.6.2 - 2026-08-11

- Fix worktree PR resolution in handoff. `_pull_request()` now falls back to `gh pr list --head <head> --state all --json number,url,headRefOid` when the default `gh pr view` probe returns no PR, resolving the worktree branch-name mismatch where the local branch (e.g. `worktree-feat+...`) differs from the remote head. `collect_context()` derives `<head>` and its OID from `meta.remote_upstream` or `meta.git_branch`; the fallback accepts exactly one OID-matching candidate, so same-named fork branches and reused branch histories cannot silently select an unrelated PR. The fallback is skipped when the capture deadline has expired. `_default_gh_runner` now accepts variadic args so the same runner can issue both probe shapes, while existing one-argument injected runners continue to degrade to empty PR fields instead of raising.

## 0.6.1 - 2026-08-09

- Bind the resume-side PR re-query to the recorded repository, not just the recorded number (adversarial-review escalation of the 0.6.0 by-number fix). PR numbers are unique only within a repo, so resuming in a different repo that also has PR #<number> could mis-attribute its state as the recorded PR's. `verify_continuity._default_gh_runner` now derives `owner/repo` from the recorded pr_url and issues `gh pr view <number> --repo owner/repo` (falling back to the unbound form only when the url is absent or unparseable), and `_check_pr` withholds the state and notes a repo mismatch when the resolved PR url differs from the recorded pr_url, catching a cross-repo collision the number check alone would miss.

## 0.6.0 - 2026-08-08

- Adversarial-review fixes to the resume-side remote and PR verification. `git_drift.recompute_remote(cwd, stored_upstream=None)` now delegates to the same prober capture uses (`session_capture.remote_state`, promoted from the former private `_remote_state`) instead of only asking for the current branch's `@{upstream}`: a branch pushed without `-u` is resolved via the same-named ref on any configured remote, and the handoff's recorded upstream rides in as a last resort when even that is gone. The result now carries the resolved `upstream` and a `pushed` flag alongside ahead/behind. `verify_continuity._check_remote` carries the stored `remote_upstream` / `remote_pushed` into the recompute and reports stored-vs-current upstream and push state, flagging `changed` on any known divergence rather than implying an unchanged remote. `verify_continuity` now re-queries the PR by its recorded number (`gh pr view <number>`), never the resume cwd's current branch, so resuming on a different branch cannot attach that branch's PR state to the recorded PR; a resolved-number mismatch or an unresolvable recorded PR withholds the state and notes why.

## 0.5.0 - 2026-08-08

- Resume-side verification helpers for the expanded handoff metadata. `git_drift.verify_commits(commits, cwd)` splits each `<shortsha> <subject>` entry and probes the sha with `git cat-file -e`, flagging a commit a rebase or force-push dropped; `git_drift.recompute_remote(cwd)` recomputes ahead/behind against `@{upstream}`, degrading to None counts with a note when there is no upstream. New `verify_continuity.py` assembles the full resume-side report: cwd match, path existence for the cobtask/TDD-plan/ADR paths, a read-only `gh pr view` state re-query (injectable runner so tests never shell out), commit resolvability, working-tree divergence via a reused `session_capture.collect_git`, and remote recompute. Every probe degrades to a structured note rather than raising, so a missing `gh`, an offline network, or a deleted PR/branch/upstream never crashes resume.

## 0.4.0 - 2026-08-08

- **Breaking:** `render_metadata_block` now takes a single `SessionMetadata` argument instead of `(sha, sha_short, branch)`. Every caller in this plugin is updated.
- Add the `SessionMetadata` dataclass: the 20 values a handoff records, each defaulting to its "nothing known" case so a caller can construct one from whatever it resolved and still render a complete block.
- `render_metadata_block` / `parse_metadata_block` cover the full key set. List-valued keys (`commits`, `adrs`) render as a `- key:` header with indented `  - item` lines; the parser collects those items only while they directly follow their header, so a stray indented bullet in prose cannot be swept into a list. Every count-valued key (`staged`, `unstaged`, `untracked`, `stash_count`, `remote_ahead`, `remote_behind`) is optional: `n/a` when the underlying probe never ran or failed, a bare integer (including 0) once it has actually answered, so a failed probe cannot be mistaken for "checked, found nothing."
- Parse returns scalars as `str | None` (`n/a` and missing keys map to None) and lists as `list[str]`. Callers that want a number coerce it themselves.
- Add `session_capture.py`: `collect_git(cwd)` reads HEAD, branch, working-tree and stash counts, upstream ahead/behind and pushed state, and the branch's commit list (capped at 20, falling back to recent history when HEAD is itself the base). Working-tree and stash counts come back `None` when their git probe fails, never a silently zeroed guess. Commit subjects have backticks stripped before capture, since a subject is attacker-influenceable text and resume's `verify_refs.extract_refs` scans the whole rendered block for backtick-delimited path tokens; leaving a backtick-wrapped `~/...` path in a subject would have let a crafted commit trigger a filesystem probe on resume. `collect_context(meta, ...)` fills in the task id and file, PR number and URL, a conditional TDD-plan link, and ADRs. The PR lookup takes an injectable `gh_runner` so tests never shell out, and skips the `gh` round-trip entirely in a repo with no remote. No hardcoded vault path: the task file is resolved from an explicit `vault_root` or `COBTASK_VAULT_ROOT`.
- Downstream effect: `context-window-resume`'s `report.meta` now carries all 20 keys instead of 3. Existing consumers of `git_sha` / `git_branch` are unaffected; resume-side verification of the new keys lands separately.

## 0.3.0 - 2026-08-08

- Add `context_filename(now=None)`: generates a collision-resistant `CONTEXT-*.md` filename (second-resolution timestamp plus a random 6-hex-char suffix) so two parallel sessions handing off within the same second never silently overwrite one another's file.

## 0.2.0 - 2026-07-19

- Add the save-path contract: `SAVE_ROOT` (`~/.claude/.sct/context-window-manager`, overridable via `CWM_SAVE_ROOT`), `repo_slug(cwd)`, and `save_dir(cwd, create=False)`. Remove the retired `CONTEXT_DIR` constant. Packaged into the context-window-manager plugin.
- `repo_slug` now returns `<basename>-<hash>` (8-hex path-derived suffix) so two repos sharing a directory basename no longer collide in the same save dir. Its git call is bounded by `_GIT_TIMEOUT` and degrades to the cwd fallback on hang/missing-git. `compute_drift` params are now type-hinted (review hardening, pre-release).
- Relocated from `skills/context-window-common/` to `lib/context-window-common/` so it is no longer discovered as an invokable slash command; it is a shared library, not a skill. `SKILL.md` renamed to `README.md`. Consumer validators/conftests updated to import from the new path. Genericized copy (pre-release).
